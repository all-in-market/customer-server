# 코드베이스 피드백 기록

아키텍처·코드 리뷰 결과를 회차별로 남기는 곳이다. 특정 PR의 리뷰 코멘트가 아니라,
**코드베이스 전반을 훑고 나온 진단**을 기록한다.

## 파일 규칙

- 파일명은 `피드백{N}차.md`. 회차는 이어붙이고, 기존 회차 파일은 수정하지 않는다.
- 각 항목은 **문제 → 근거(파일:라인) → 원인 → 해결 → 검증** 순서로 쓴다.
  근거 없는 지적은 남기지 않는다.
- 우선순위를 매기고, 이번 회차에서 제외한 항목도 함께 적어 다음 회차가 중복 조사하지 않게 한다.

## 다른 문서와의 경계

| 남길 곳 | 무엇을 |
|---|---|
| `docs/feedback/피드백{N}차.md` | 진단 — "무엇이 왜 문제인가" |
| [../technical-decisions.md](../technical-decisions.md) | 그 결과 내린 기술 선택과 대안 검토 (TD-00N) |
| [../troubleshooting.md](../troubleshooting.md) | 실제 장애의 증상·조사·해결 (TR-00N) |
| `docs/improvement/` | 개선의 측정 결과 (EXPLAIN ANALYZE, k6 전후 비교, 그래프) |

피드백 항목이 실제 작업으로 넘어가면, 근거와 판단은 위 표에 따라 해당 문서로 옮기고
피드백 파일은 그대로 둔다(그 시점의 진단 기록이므로 갱신하지 않는다).
